# Argus 默认启动验收

## 修复范围

安装包必须自行包含启动所需的默认设置。用户无需安装数据库、创建数据库账号、修改目录权限或填写启动参数。

- Windows 安装器保留数据库运行文件、应用专用 VC++ 运行库、Unicode 桌面快捷方式与启动日志。
- macOS 与 Linux 在构建阶段下载并校验数据库运行文件，然后放入发行包。首次启动使用包内缓存。
- 程序自动选择当前用户的数据目录，安装目录可以只读；配置、数据库和日志不写入应用安装目录。
- 桌面启动器自动打开本机工作台；macOS 启动失败时显示日志位置。Unix 启动器仅对明确请求的更新重启，不再反复重试启动错误。
- Docker 镜像内置普通系统用户、目录权限、数据库与浏览器运行文件，使用 `/data` 保存持久数据。
- Compose 默认使用单个 Argus 服务与命名数据卷，不要求 `.env`、数据库密码或外部 PostgreSQL。
- 用户自己的模型供应商、API 地址与密钥在应用内设置，发行包不携带私人凭据。

## 本地真实结果（2026-10-25）

| 候选包 | 启动方式 | 测试条件 | 结果 |
| --- | --- | --- | --- |
| Linux ARM64 | 原始 `start.sh`，无参数 | Docker ARM64、断网、安装目录只读、普通 OS 用户、无 Argus 环境变量 | PASS：数据库、HTML/JS、API、中文会话重启持久化 |
| Linux amd64 | 原始 `start.sh`，无参数 | Docker x86-64 模拟、断网、安装目录只读、普通 OS 用户、无 Argus 环境变量 | PASS：数据库、HTML/JS、API、中文会话重启持久化 |
| macOS ARM64 | 原始 `.app/Contents/MacOS/Argus`，无参数 | 本机 M5、全新用户数据目录、无数据库配置 | PASS：数据库、HTML/JS、API、中文会话重启持久化 |

macOS 测试使用独立 HOME 隔离测试数据；Linux 测试镜像只提供正常操作系统账号及其 HOME。这些属于测试环境，不向 Argus 提供数据库、数据路径、身份验证等专用设置，也不修改被测启动器或二进制。

## 发布门禁

`scripts/smoke-release.py` 对原始包启动器执行首次启动与重启验收。发布工作流对两种 Linux 架构执行断网、只读安装测试，对 macOS ARM64 执行原始应用启动器测试，并保留 Windows 原生安装器、中文路径、桌面快捷方式与离线数据库测试。测试失败不会上传相应安装包。

`scripts/smoke-container.py` 在镜像发布后使用其默认入口启动，禁用容器网络，不传应用参数、应用环境变量、用户或目录覆盖；检查非 root 用户、数据库、HTML、日志及重启后的数据保留。实际结果以对应 release 工作流为准。

## 验收边界

- Docker 的 Linux x86-64 模拟测试不等于物理 Windows Intel/AMD 电脑测试；Windows 依赖原生 CI 测试，并需持续收集用户机器结果。
- macOS 内部启动器测试不等于 Gatekeeper 公证验收。下载后无警告打开仍需要发布者的 Apple Developer ID 签名和公证；没有这些凭据时不能声称该问题已解决。
- 启动验收没有配置私人模型密钥，不代表真实模型调用或 SRC Golden E2E 全链路通过。
- 不更改或删除用户已有的外部 PostgreSQL 数据卷；旧部署迁移需另行验证。
